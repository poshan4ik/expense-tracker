# ЗАЩИТА — Трекер расходов

## 1. Что делает программа

Программа «Трекер расходов» — это дневник трат на Python. Пользователь вводит
сумму, категорию, дату и описание, нажимает «Сохранить» — запись появляется
в плоской таблице (Дата, Категория, Сумма, Описание) и сохраняется в базу
данных SQLite, которая не стирается после закрытия программы. Есть фильтр
по категории и вкладка «Статистика»: карточка «Всего потрачено» и круговая
диаграмма по категориям. Неверный ввод не роняет программу — появляется
окно с понятной ошибкой.

## 2. Зачем нужен каждый файл

| Файл | Зачем нужен | Строк |
|---|---|---|
| `main.py` | Точка входа: запускает окно программы | 9 |
| `app.py` | Интерфейс: форма, таблица, вкладки, кнопки (без SQL) | 317 |
| `logic.py` | Бизнес-логика: проверка ввода и расчёты (без интерфейса) | 79 |
| `database.py` | Работа с базой SQLite: создать таблицу, добавить, прочитать | 84 |
| `theme.py` | Тема: все цвета, шрифты и размеры в одном месте | 48 |
| `requirements.txt` | Список библиотек: `customtkinter`, `matplotlib` | — |
| `README.md` | Инструкция: как запустить и как пользоваться | — |

Идея: каждый файл отвечает за одно. Хочешь поменять цвет — идёшь в `theme.py`,
баг в расчётах — ищи в `logic.py`, проблема с сохранением — `database.py`.

## 3. Как работает по шагам

### Кнопка «Сохранить» (app.py:134)

1. Кнопка вызывает метод `save_expense` (app.py:223).
2. Поля формы проверяются функцией `validate_expense_input`
   (logic.py:41): сумма — положительное число, категория выбрана,
   дата в формате ДД.ММ.ГГГГ.
3. Если проверка не прошла — `ValueError` (logic.py:22, 37) ловится
   в `except` (app.py:229) и появляется окно с ошибкой. Программа не падает.
4. Если всё верно — `add_expense` (database.py:43) делает SQL-команду
   `INSERT INTO expenses ... VALUES (?, ?, ?, ?)` и запись лежит в `expenses.db`.
5. Поля формы очищаются, вызываются `load_expenses` (app.py:248) и
   `update_stats` (app.py:277) — таблица и статистика перерисовываются.

### Фильтр по категории (app.py:150)

1. Пользователь выбирает категорию в выпадающем списке.
2. Срабатывает метод `_on_filter_change` (app.py:244) → `load_expenses`.
3. `get_expenses` (database.py:62) делает `SELECT ... WHERE category = ?`.
   Выбрано «Все» — `WHERE` нет, показываются все записи.

## 4. Сложные места простыми словами

- **Плоская таблица** — `ttk.Treeview` с `show="headings"` (app.py:160):
  обычные строки с колонками Дата, Категория, Сумма, Описание.
- **Диаграмма** — `draw_chart` (app.py:283) берёт словарь `{категория: сумма}`
  от `sum_by_category` (logic.py:61) и рисует круг `matplotlib` (`axes.pie`).
  Старая диаграмма перед новым рисунком удаляется, чтобы они не накапливались.
- **SQLite** — файл базы данных `expenses.db` рядом с программой. Команды
  SQL (`INSERT`, `SELECT`) выполняются в `database.py`. Символ `?`
  в запросе — заглушка под значение: так безопаснее, чем вставлять текст
  прямо в SQL.
- **validate** (проверка) — функции в `logic.py`, которые превращают текст
  из полей в чистые значения (float, date) или бросают `ValueError`
  с человеческим текстом («Сумма должна быть положительной»).
- **Пустые состояния** — если база пуста, в таблице строка-подсказка
  «Пока нет расходов» (app.py:259), а на диаграмме — такая же надпись
  вместо пустого круга.
- **`self`** — это само окно (объект `ExpenseApp`). Через `self` методы
  хранят «память»: ссылки на виджеты, текущий фильтр.

## 6. 20 вопросов с ответами

1. **Что за библиотека `customtkinter`?** Улучшенный tkinter: современные кнопки
   и тёмная тема. Обычный tkinter выглядит как Windows 98.
2. **Что делает `sqlite3`?** Модуль из Python для работы с базой данных
   в файле. Дополнительно ставить не нужно.
3. **Зачем `requirements.txt`?** Список библиотек: `pip install -r
   requirements.txt` ставит их одной строкой.
4. **Почему `?` в SQL-запросах?** Это защита от SQL-инъекций: значение
   подставляется отдельно от текста запроса.
5. **Что делает `with get_connection() as conn`?** `with` сам закрывает
   соединение и сохраняет изменения.
6. **Как база узнаёт про таблицу?** `init_db` (database.py:23) выполняет
   `CREATE TABLE IF NOT EXISTS` — создаёт таблицу, только если её ещё нет.
7. **Что делает `validate_amount`?** Проверяет, что сумма — положительное
   число. Принимает текст («1500», «1500,5»), возвращает float.
8. **Что такое `ValueError`?** Стандартная ошибка Python: «значение не подходит».
   Мы её вызываем сами (`raise ValueError("Введите сумму")`) и ловим в окне.
9. **Почему после ошибки программа не падает?** Потому что ошибка ловится:
   `try: ... except ValueError: messagebox.showwarning(...)` (app.py:226-232).
10. **Как считаются итоги?** `len(expenses)` — количество; `total_sum`
    (logic.py:53) в цикле складывает суммы.
11. **Как работает фильтр?** Выбранная категория уходит в `get_expenses`
    (database.py:62) и SQL получает `WHERE category = ?`. Выбрано «Все» —
    `WHERE` нет.
12. **Что показывается при пустой базе?** Строка-подсказка «Пока нет
    расходов» в таблице и такая же надпись вместо диаграммы.
13. **Что показывает итоговая строка?** «Записей: N · Итого: X ₸» —
    `update_summary` (app.py:270).
14. **Как работает диаграмма?** `sum_by_category` собирает `{категория: сумма}`,
    `axes.pie` рисует круг, `FigureCanvasTkAgg` встраивает его в окно tkinter.
    Импорты matplotlib — в начале файла (app.py:13-17).
15. **Какие цвета и шрифты?** Все в `theme.py`: тёмный фон `#0F1117`,
    акцент `#6C63FF`, шрифт Segoe UI.
16. **Как сохраняется дата?** В базе — текст `YYYY-MM-DD` (`.isoformat()`),
    в поле ввода — `ДД.ММ.ГГГГ`; превращает одно в другое `validate_date`.
17. **Зачем `AUTOINCREMENT`?** id записи растёт сам: 1, 2, 3...
    Не нужно придумывать номера вручную.
18. **Где лежат данные?** В файле `expenses.db` рядом с программой.
    В `.gitignore`, чтобы случайно не залить в репозиторий.
19. **Как запустить?** `pip install -r requirements.txt`, затем
    `python main.py`. Нужен Python 3.10+.
20. **А если захочу добавить удаление?** Новая кнопка в `_build_table`
    (app.py:137), метод с `DELETE FROM expenses WHERE id = ?` в
    `database.py` и перерисовка таблицы — как в разделе 8, доработка 1.

## 7. Шпаргалка на 2 минуты

1. Приветствие: «Мой проект — трекер расходов: дневник трат на Python.
   Пользователь добавляет траты, они сохраняются в базе SQLite и
   визуализируются на вкладке статистики.»
2. Технологии: Python, customtkinter (интерфейс), sqlite3 (база),
   matplotlib (диаграмма). Всего 5 файлов, ~540 строк.
3. Живая демонстрация (если дадут компьютер):
   - добавить трату: 1500, Еда, описание «обед» → Сохранить;
   - показать: появилась строка в таблице, итог под таблицей;
   - включить фильтр «Еда» — таблица показывает только еду;
   - вкладка «Статистика»: «Всего потрачено» и круговая диаграмма;
   - ввести мусор в сумму → окно «Сумма должна быть числом» — программа жива.
4. Ключевая архитектура: интерфейс (`app.py`) ничего не знает про SQL;
   логика (`logic.py`) ничего не знает про интерфейс; база (`database.py`)
   — отдельный слой с SQL.
5. Что умеет: проверка ввода с внятными ошибками, фильтр по категории,
   «Всего потрачено» + круговая диаграмма, пустые состояния.
6. Что можно улучшить: удаление записей, экспорт в JSON, фильтр по месяцу,
   светлая тема (подробности в разделе 8).

## 8. Три доработки, о которых может спросить преподаватель

### 1) Экспорт расходов в файл JSON

**Где:** новая кнопка в `_build_table` (app.py:137), новая функция
`export_expenses` в `app.py`, данные брать из `get_expenses` (database.py:62).
**Что делаем:** кнопка «Экспорт» → `json.dump` списка расходов в
`expenses.json` (модуль `json` из стандартной библиотеки).
**Почему легко:** данные уже есть в памяти, нужен один цикл и одна команда.

### 2) Фильтр по месяцу

**Где:** список фильтра `FILTER_CATEGORIES` (theme.py:29) и функция
`get_expenses` (database.py:62).
**Что делаем:** в выпадающий фильтр добавить месяцы («Октябрь 2026», ...),
а в SQL — `WHERE date LIKE '2026-10%'` (дата лежит как `2026-10-12`,
месяц — первые 7 символов).
**Почему легко:** SQL уже умеет `WHERE`, добавляется одна строка условия
плюс сбор списка месяцев из базы.

### 3) Переключатель светлой и тёмной темы

**Где:** настройки окна в `__init__`/`_build_ui` (app.py:57, app.py:72),
константы в theme.py:8-14.
**Что делаем:** кнопка-переключатель вызывает
`ctk.set_appearance_mode("light")` / `("dark")` — встроенная возможность
customtkinter.
**Оговорка:** цвета наших карточек захардкожены в `theme.py`, поэтому
полностью светлая тема потребует второй набор цветов (например, словарь
`THEMES = {"dark": ..., "light": ...}`). Это главная сложность —
учитывать, что константы сейчас глобальные.
